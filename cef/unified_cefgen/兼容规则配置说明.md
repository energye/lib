# CEF 统一层兼容规则配置说明

`compat_rules.json` 用来处理一种情况：同一个接口、同一个方法名，在不同 CEF 版本里的参数或返回值不一样，但我们确认它们语义相同，希望统一成一个公共方法。

生成器会自动处理少量非常安全的差异，例如简单整数扩宽。其它同名异签名方法会写入 `compat_report.md` 的“未兼容的同名异签名方法”。确认语义一致后，再把规则写到 `compat_rules.json`。

## 使用流程

1. 运行生成器。
2. 打开 `cef/compat_report.md`。
3. 找到“未兼容的同名异签名方法”。
4. 判断这些方法是不是同一个语义。
5. 如果语义一致，就在 `compat_rules.json` 里加规则。
6. 重新运行生成器并编译所有目标版本。

```powershell
go run .
go test -run '^$' ./cef
go test -run '^$' -tags CEF127 ./cef
go test -run '^$' -tags CEF147 ./cef
```

## 顶层结构

```json
{
  "types": {
    "TCefFrameIdentifier": "string"
  },
  "methods": {
    "ICefFrame.GetIdentifier": {
      "description": "把不同版本的 frame id 统一成不透明字符串标识。",
      "common": {
        "params": [],
        "results": [{ "type": "TCefFrameIdentifier" }],
        "result": [{ "kind": "identifier_string" }]
      },
      "versions": {}
    }
  }
}
```

`types` 用来声明统一层新增类型。  
`methods` 用来声明某个方法的统一签名和各版本转换方式。

## types

`types` 会在生成的 `interfaces.go` 里输出统一层类型。

```json
{
  "types": {
    "TCefFrameIdentifier": "string"
  }
}
```

生成结果：

```go
type TCefFrameIdentifier string
```

适合用于“不想暴露底层版本差异”的类型。例如某个版本返回 `int64`，另一个版本返回 `string`，但业务上它们都是“不透明 ID”，就可以定义一个统一类型。

## methods

`methods` 的 key 格式是：

```text
接口名.方法名
```

例如：

```json
{
  "methods": {
    "ICefFrame.GetIdentifier": {}
  }
}
```

每个方法规则通常包含：

- `description`：给人看的说明，不参与生成。
- `common`：公共方法签名，以及默认转换规则。
- `versions`：某些版本的特殊转换规则。

## common

`common` 有两个作用：

1. 定义统一层公共方法签名。
2. 作为所有版本的默认转换配置。

```json
"common": {
  "params": [
    { "name": "index", "type": "uint32" }
  ],
  "results": []
}
```

`params` 是公共方法参数。  
`results` 是公共方法返回值。

如果不写 `params` 或 `results`，生成器会使用 `latestVersion` 对应版本的方法签名作为默认值。建议对有差异的方法显式写出来，避免以后升级版本时默认签名被新版本影响。

注意区分两个名字很像的字段：

- `results`：公共方法“返回值签名”。
- `result`：raw 返回值到公共返回值的“转换规则”。

## versions

`versions` 用来覆盖某个版本的转换方式。

```json
"versions": {
  "109": {
    "args": ["int32(index)"]
  }
}
```

继承规则：

- 如果某个版本没有配置，就使用 `common` 里的转换配置。
- 如果某个版本只配置了一部分字段，没配置的字段继续使用 `common`。
- `imports` 会和 `common.imports` 合并，版本配置优先。
- `result`、`pre`、`args`、`post`、`returns`、`bodyHelper` 配了就覆盖 `common`。
- `versions` 可以是空对象 `{}`，表示所有版本都用 `common` 的转换配置。

## 常用组合

### 1. 返回值类型不同，但语义相同

例如 109 返回数字，新版本返回字符串，都表示同一个 frame id。

```json
"ICefFrame.GetIdentifier": {
  "description": "把 frame id 统一成不透明字符串标识。",
  "common": {
    "params": [],
    "results": [{ "type": "TCefFrameIdentifier" }],
    "result": [{ "kind": "identifier_string" }]
  },
  "versions": {}
}
```

生成效果：

```go
func (t *tICefFrame_109) GetIdentifier() TCefFrameIdentifier {
    r0 := t.raw.GetIdentifier()
    return TCefFrameIdentifier(strconv.FormatInt(int64(r0), 10))
}
```

### 2. 参数类型不同，但调用语义相同

例如 109 是 `int32`，新版本是 `uint32`，统一层希望暴露 `uint32`。

```json
"ICEFOSRIMEHandler.UpdateCaretPosition": {
  "description": "统一 caret index 为 uint32。",
  "common": {
    "params": [
      { "name": "index", "type": "uint32" }
    ],
    "results": []
  },
  "versions": {
    "109": {
      "args": ["int32(index)"]
    }
  }
}
```

生成效果：

```go
func (t *tICEFOSRIMEHandler_109) UpdateCaretPosition(index uint32) {
    t.raw.UpdateCaretPosition(int32(index))
}
```

### 3. 调用前需要准备变量

使用 `pre` 准备 raw 调用需要的值，再用 `args` 指定 raw 调用参数。

```json
"versions": {
  "109": {
    "pre": [
      "rawIndex := int32(index)"
    ],
    "args": [
      "rawIndex"
    ]
  }
}
```

生成顺序是：

1. 写入 `pre`。
2. 调用 `t.raw.Method(args...)`。
3. 写入 `post`。
4. 处理返回值。

### 4. 返回值需要完整自定义

如果自动 `result` 规则不够用，可以用 `returns` 直接指定返回表达式。

```json
"versions": {
  "109": {
    "returns": [
      "TCefFrameIdentifier(strconv.FormatInt(int64(r0), 10))"
    ],
    "imports": {
      "strconv": "strconv"
    }
  }
}
```

`returns` 里可以使用 `{r0}`、`{r1}` 这种 raw 返回值占位符。上面也可以写成：

```json
"returns": [
  "TCefFrameIdentifier(strconv.FormatInt(int64({r0}), 10))"
]
```

### 5. 逻辑比较复杂，交给辅助函数

如果转换逻辑很长，不要把大量代码写进 JSON。建议写一个 Go helper，然后用 `bodyHelper`。

```json
"versions": {
  "109": {
    "bodyHelper": "compat.CefFrameGetIdentifier109",
    "args": ["{raw}"],
    "imports": {
      "compat": "github.com/energye/cef/cef/internal/compat"
    }
  }
}
```

生成效果：

```go
func (t *tICefFrame_109) GetIdentifier() TCefFrameIdentifier {
    return compat.CefFrameGetIdentifier109(t.raw)
}
```

如果 `bodyHelper` 没写 `args`，默认参数是：

```text
{raw}, {p0}, {p1}, ...
```

## result 规则

`result` 按返回值顺序配置，每个返回值对应一个规则。

支持的写法：

```json
"result": [
  { "kind": "identity" }
]
```

```json
"result": [
  { "kind": "cast" }
]
```

```json
"result": [
  { "kind": "identifier_string" }
]
```

```json
"result": [
  { "helper": "compat.NormalizeValue" }
]
```

```json
"result": [
  { "expr": "TUnifiedValue({value})" }
]
```

含义：

- `identity`：原样返回。
- `cast`：使用 Go 类型转换，例如 `T(x)`。
- `identifier_string`：把整数或字符串统一成字符串标识类型。
- `helper`：调用一个辅助函数转换单个返回值。
- `expr`：写一个表达式模板，`{value}` 表示 raw 返回值。

## pre / args / post / returns

这些字段用于控制 raw 调用前后生成的代码。

```json
"versions": {
  "109": {
    "pre": [
      "rawIndex := int32(index)"
    ],
    "args": [
      "rawIndex"
    ],
    "post": [],
    "returns": []
  }
}
```

字段含义：

- `pre`：raw 调用前插入的代码。
- `args`：传给 raw 方法的参数列表。
- `post`：raw 调用后插入的代码。
- `returns`：最终 return 的表达式列表。

注意：

- `args` 是 raw 方法的参数，不是公共方法的参数。
- 如果 raw 参数名和 common 参数名不一致，建议显式写 `args`。
- `post` 可以使用 `{raw}`、`{参数名}`、`{p0}` 这类参数占位符。
- `returns` 可以使用 `{r0}`、`{r1}` 这类 raw 返回值占位符。

## imports

如果规则里使用了外部包，必须写 `imports`。

```json
"imports": {
  "strconv": "strconv",
  "compat": "github.com/energye/cef/cef/internal/compat"
}
```

`common.imports` 和 `versions.<版本>.imports` 会合并。版本里的同名 alias 会覆盖 common。

## 占位符

常用占位符：

- `{raw}`：当前 wrapper 的 raw 对象，也就是 `t.raw`。
- `{参数名}`：公共方法参数，例如 `{index}`。
- `{p0}`、`{p1}`：按位置访问公共方法参数。
- `{r0}`、`{r1}`：raw 调用返回值，只用于 `returns`。
- `{value}`：单个 raw 返回值，只用于 `result.expr`。

## 注意事项

- 只有确认语义相同的方法才应该配置统一规则。
- 不要只因为方法名相同就强行统一。
- 从有符号整数转无符号整数，或者从大范围类型转小范围类型，要确认不会溢出。
- `args` 里写的是 Go 表达式，会直接进入生成代码。
- `pre`、`post`、`returns` 也会直接进入生成代码，只能写可信配置。
- `bodyHelper` 适合复杂逻辑，JSON 里不要堆太长的代码。
- 多返回值方法建议显式写 `results` 和 `result` 或 `returns`。
- 新增 CEF 版本后，必须重新看 `compat_report.md`，确认旧规则是否仍然适用。

## 不建议使用的方式

当前配置结构里有 `raw` 字段，但生成器还没有用它做 raw 签名选择。现在不要依赖 `raw` 解决重载或同名多签名问题。遇到这种情况，优先用 `args`、`result`、`returns` 或 `bodyHelper` 明确转换。

## 推荐写法

简单差异优先用内置规则：

- 只需要类型转换：用 `result.kind = "cast"`。
- ID 数字和字符串统一：用 `result.kind = "identifier_string"`。
- 某个版本参数需要强转：在该版本写 `args`。

复杂差异优先用 helper：

- 需要多行判断。
- 需要临时对象。
- 需要调用其它包。
- 需要处理中间错误或特殊值。

这样配置文件保持清楚，生成器生成的代码也更容易检查。
