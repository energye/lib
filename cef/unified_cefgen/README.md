# cefgen 使用说明

`cefgen` 用于把多个 CEF 版本目录中的 Go 源码统一成一层兼容 API。当前生成器读取 `109`、`127`、`147` 三个版本的 `cef` 和 `types` 包，生成统一接口、版本适配器、类型别名和兼容性报告。

## 目录约定

当前工具的路径和版本号写在 [main.go](C:/app/workspace/gen/gout/cef/cefgen/main.go:19) 的常量中，没有命令行参数：

```go
const (
	modulePath     = "github.com/energye/cef"
	baseDir        = `C:\app\workspace\gen\gout\cef`
	outputDir      = `C:\app\workspace\gen\gout\cef\cef`
	latestVersion = "147"
	defaultVersion = "109"
)

var versions = []string{"109", "127", "147"}
```

默认工程结构如下：

```text
C:\app\workspace\gen\gout\cef
+-- go.mod
+-- 109
|   +-- cef
|   +-- types
+-- 127
|   +-- cef
|   +-- types
+-- 147
|   +-- cef
|   +-- types
+-- cef
|   +-- 生成输出目录
+-- cefgen
    +-- main.go
    +-- README.md
```

如果工程路径、模块路径或 CEF 版本发生变化，需要先修改 `main.go` 中的 `modulePath`、`baseDir`、`outputDir`、`latestVersion`、`defaultVersion` 和 `versions`。

## 环境要求

- Go 1.18 或更高版本。源码使用了泛型函数。
- `baseDir` 下必须已经存在各版本的 `cef` 和 `types` Go 包。
- 在目标平台上运行生成器。工具会按当前 `runtime.GOOS` 过滤 `*_windows.go`、`*_linux.go`、`*_darwin.go` 文件，因此 Windows、Linux、macOS 生成结果可能包含不同的平台专用 API。

## 运行生成

在 `cefgen` 目录执行：

```powershell
cd C:\app\workspace\gen\gout\cef\cefgen
go run .
```

也可以先构建再运行：

```powershell
cd C:\app\workspace\gen\gout\cef\cefgen
go build -o cefgen.exe .
.\cefgen.exe
```

运行时会打印每个版本解析到的接口、函数、CEF 类型和枚举类型数量，例如：

```text
CEF 109: ... interfaces, ... functions, ... cef types, ... enum/types
CEF 127: ... interfaces, ... functions, ... cef types, ... enum/types
CEF 147: ... interfaces, ... functions, ... cef types, ... enum/types
generated unified CEF layer into C:\app\workspace\gen\gout\cef\cef
```

## 生成内容

生成器会先清理 `outputDir` 中由它管理的文件和目录，再重新生成：

- `init.go`：统一的 `cef.Init()`，内部调用 `github.com/energye/cef/base.Init()`。
- `raw.go`：定义基础 `Raw` 别名、`IRaw` 接口和 `RawAs[T]` helper，用于显式获取底层对象。
- `interfaces.go`：跨版本公共接口定义。
- `adapter_109.go`、`adapter_127.go`、`adapter_147.go`：各版本的适配器、包装类型、构造函数和普通函数转发。
- `types/types_109.go`、`types/types_127.go`、`types/types_147.go`：各版本 `types` 包的类型和常量别名。
- `compat_report.md`：接口公共方法和版本专有方法数量报告。

清理范围只包括以下生成物：`adapter_*.go`、`interfaces.go`、`init.go`、`raw.go`、`compat_report.md`、`types` 目录。输出目录中的其他文件不会被主动删除。

## 构建标签

版本适配文件和 `types` 别名文件都带有构建标签。当前 `defaultVersion` 是 `109`，所以不指定任何 CEF 版本标签时会默认使用 CEF 109：

```go
//go:build CEF109 || (!CEF109 && !CEF127 && !CEF147)
//go:build CEF127
//go:build CEF147
```

默认构建：

```powershell
go build ./...
```

需要切换到其它 CEF 版本时，显式指定版本标签。例如：

```powershell
go build -tags CEF147 ./...
```

同一次构建应只选择一个 CEF 版本标签，避免多个版本的适配文件同时进入编译。只要指定了任意版本标签，默认版本条件就不会生效。

## 生成规则

工具会解析每个版本 `cef` 包中的导出接口和导出函数，以及 `types` 包中的导出类型和常量。

接口处理规则：

- 只解析名称以 `I` 开头的接口。
- 只输出以 `ICef`、`IChromium`、`ICEF`、`IEng`、`IPDF` 开头的接口。
- 跳过 `IObject`、`IComponent`、`IWinControl`、`IStrings`、`IStream`、`IBitmap`。
- 跨全部版本都存在的方法会写入公共接口。
- 只存在于部分版本的方法会写入对应版本的 `接口名_版本号` 接口。
- 内嵌接口会递归补齐，但外部包别名形式的内嵌接口会被过滤。

函数处理规则：

- 导出函数会被采集。
- 返回统一接口的函数会生成转发包装。
- 名称以 `Cef` 开头的函数会生成转发包装。
- 无返回值且名称以 `Cef` 或 `Set` 开头的函数会生成转发包装。

类型处理规则：

- 每个版本 `cef` 包中的导出非接口类型会在对应 `adapter_*.go` 中生成别名。
- 每个版本 `types` 包中的导出类型和常量会在 `types/types_*.go` 中生成别名。
- 已纳入统一接口的 CEF 类型不会再作为普通类型别名输出。

## 增加或切换 CEF 版本

1. 在 `baseDir` 下准备新版本目录，例如 `151/cef` 和 `151/types`。
2. 修改 `versions`，把新版本加入列表。
3. 如果新版本应作为公共注释和方法选择的基准，修改 `latestVersion`。
4. 如果新版本应作为无标签构建时的默认版本，修改 `defaultVersion`。
5. 运行 `go run .` 重新生成。
6. 检查 `cef/compat_report.md` 和生成后的 `adapter_*.go`。
7. 使用默认构建和对应构建标签验证，例如 `go test ./...`、`go test -tags CEF151 ./...`。

## 常见问题

### parse cef package 或 parse types package 报错

检查 `baseDir` 和版本目录是否存在，并确认目录下有合法的 Go 源文件：

```text
<baseDir>\<version>\cef
<baseDir>\<version>\types
```

### 生成后缺少某个平台 API

确认生成器是在目标平台运行的。文件名带平台后缀时，只有匹配当前 `runtime.GOOS` 的文件会被解析。

### 构建时报重复定义

通常是同时启用了多个 CEF 版本标签。重新构建时不传版本标签使用默认版本，或只传一个显式版本标签，例如：

```powershell
go build -tags CEF147 ./...
```

### 新接口没有出现在 `interfaces.go`

检查接口名是否满足输出前缀规则，且没有落入跳过列表。当前规则在 `shouldIncludeInterface` 和 `shouldSkipInterface` 中维护。

## 维护建议

- 生成器目前没有命令行参数，路径和版本调整都需要改源码常量。
- 生成结果带有 `Code generated by cefgen. DO NOT EDIT.`，应修改源版本包或生成器本身后重新生成。
- 修改生成逻辑后，建议至少执行一次 `go run .`，再执行默认构建和目标版本标签构建，例如 `go test ./...`、`go test -tags CEF147 ./...`。
